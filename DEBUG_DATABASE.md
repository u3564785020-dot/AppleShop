# 🔍 Диагностика: Почему нет данных в MongoDB

## Проблема: MongoDB пустая, хотя подключение успешно

Если MongoDB показывает "You have no collections", это означает, что данные не сохраняются. Давайте проверим все возможные причины.

## Шаг 1: Проверка работы Backend

### 1.1. Проверка статуса Backend сервиса

1. В Railway перейдите в ваш **Backend сервис**
2. Проверьте вкладку **"Deployments"**:
   - ✅ Статус должен быть **"Deployment successful"** (зелёный)
   - ❌ Если **"Failed"** (красный) - бэкенд не работает

### 1.2. Проверка логов Backend

1. В Backend сервисе откройте вкладку **"Logs"** или **"Deployments" → "View logs"**
2. Ищите следующие сообщения:

**✅ Должны быть:**
```
MongoDB Connected: mongodb.railway.internal:27017
Server running on port 3001
Environment: production
```

**❌ Если видите ошибки:**
- `MongoDB connection error` - проблема с подключением к БД
- `Error: MongoDB URI is not defined` - не установлена переменная `MONGODB_URI`
- `Cannot find module` - отсутствуют зависимости
- `Port already in use` - проблема с портом

### 1.3. Проверка Health Endpoint

1. В Backend сервисе найдите **Public URL** (например: `https://your-backend.up.railway.app`)
2. Откройте в браузере:
   ```
   https://your-backend-url.up.railway.app/health
   ```
3. Должен вернуться JSON:
   ```json
   {
     "status": "OK",
     "timestamp": "...",
     "environment": "production"
   }
   ```
4. Если получаете ошибку или `Cannot GET /health` - бэкенд не запущен!

## Шаг 2: Проверка переменных окружения

### 2.1. Backend переменные

В Backend сервисе → **"Variables"** должны быть:

```
MONGODB_URI=mongodb://mongo:...@mongodb.railway.internal:27017
FRONTEND_URL=https://appleshop-production-ae28.up.railway.app
NODE_ENV=production
```

**Проверьте:**
- ✅ `MONGODB_URI` существует и имеет значение
- ✅ `FRONTEND_URL` указывает на ваш фронтенд (без `/api` в конце)
- ✅ Нет опечаток (например, `ODE_ENV` вместо `NODE_ENV`)

### 2.2. Frontend переменные

В Frontend сервисе → **"Variables"** должна быть:

```
REACT_APP_API_URL=https://your-backend-url.up.railway.app/api
```

**Проверьте:**
- ✅ Переменная существует
- ✅ URL правильный (замените `your-backend-url` на реальный URL)
- ✅ В конце есть `/api`

## Шаг 3: Проверка запросов с фронтенда

### 3.1. Откройте консоль браузера

1. Откройте ваш фронтенд-сайт
2. Нажмите **F12** (открыть DevTools)
3. Перейдите на вкладку **"Console"**

### 3.2. Проверка инициализации пользователя

При первой загрузке страницы должны появиться:

**✅ Если всё работает:**
```
(нет ошибок в консоли)
```

**❌ Если есть проблемы:**
```
Error initializing user: Failed to fetch
Error initializing user: NetworkError
CORS error
```

Если видите ошибки - бэкенд недоступен или неправильный URL.

### 3.3. Проверка Network запросов

1. В DevTools перейдите на вкладку **"Network"**
2. Обновите страницу (F5)
3. Ищите запросы к `/api/user`:
   - ✅ Должен быть запрос `POST /api/user` со статусом **200** или **201**
   - ❌ Если **404** - неправильный URL бэкенда
   - ❌ Если **CORS error** - проблема с CORS настройками
   - ❌ Если **Failed to fetch** - бэкенд недоступен

## Шаг 4: Выполнение действий, которые сохраняют данные

Данные сохраняются только при выполнении определённых действий:

### 4.1. Инициализация пользователя (автоматически)

**Когда происходит:** При первой загрузке сайта

**Что проверяет:**
1. Откройте сайт
2. В консоли браузера (F12) проверьте запрос `POST /api/user`
3. В логах бэкенда должно появиться:
   ```
   POST /api/user
   Creating new user...
   ```

**Проверка в MongoDB:**
- В Railway → MongoDB → Database → Data
- Должна появиться коллекция `users`
- Должен появиться документ с `clientId`

### 4.2. Добавление товара в корзину

**Когда происходит:** При клике "Add to Cart"

**Что проверяет:**
1. Добавьте товар в корзину на фронтенде
2. В консоли браузера (Network) должен появиться запрос `POST /api/user/cart`
3. В логах бэкенда должно появиться:
   ```
   POST /api/user/cart
   Updating cart for clientId: ...
   ```

**Проверка в MongoDB:**
- Откройте коллекцию `users` в MongoDB
- Найдите документ пользователя
- В поле `cart` должен быть массив с товарами

### 4.3. Заполнение формы доставки

**Когда происходит:** При нажатии "Proceed to Payment" на странице `/en/shipbox`

**Что проверяет:**
1. Добавьте товары в корзину
2. Перейдите на страницу корзины (`/en/cart`)
3. Нажмите "Proceed to Checkout"
4. Заполните форму доставки
5. Нажмите "Proceed to Payment"
6. В консоли браузера (Network) должен появиться запрос `POST /api/user/checkout`
7. В логах бэкенда должно появиться:
   ```
   POST /api/user/checkout
   Saving checkout data for clientId: ...
   ```

**Проверка в MongoDB:**
- Откройте коллекцию `users` в MongoDB
- Найдите документ пользователя
- В поле `checkout` должны быть данные формы

## Шаг 5: Пошаговая диагностика

### Тест 1: Работает ли бэкенд?

```bash
# Откройте в браузере:
https://your-backend-url.up.railway.app

# Должен вернуться JSON с информацией об API
```

**Если не работает:** Проверьте логи бэкенда на Railway.

### Тест 2: Подключен ли бэкенд к MongoDB?

В логах бэкенда ищите:
```
MongoDB Connected: ...
```

**Если нет этого сообщения:** Проверьте переменную `MONGODB_URI` в бэкенде.

### Тест 3: Может ли фронтенд достучаться до бэкенда?

1. Откройте фронтенд
2. F12 → Network
3. Обновите страницу
4. Ищите запросы к `/api/user`

**Если нет запросов:** Проверьте переменную `REACT_APP_API_URL` во фронтенде.

**Если запросы есть, но с ошибками:**
- **404**: Неправильный URL (добавьте `/api` в конце)
- **CORS error**: Проверьте `FRONTEND_URL` в бэкенде
- **Failed to fetch**: Бэкенд недоступен

### Тест 4: Сохраняются ли данные?

1. Добавьте товар в корзину
2. Проверьте логи бэкенда - должен быть запрос `POST /api/user/cart`
3. Подождите несколько секунд
4. Проверьте MongoDB → Database → Data → users

**Если данных нет:**
- Проверьте логи бэкенда на ошибки при сохранении
- Убедитесь, что MongoDB сервис запущен

## Частые проблемы и решения

### ❌ Проблема: Запросы не отправляются с фронтенда

**Причины:**
1. Неправильный `REACT_APP_API_URL`
2. Бэкенд не запущен
3. CORS ошибка

**Решение:**
1. Проверьте `REACT_APP_API_URL` в переменных фронтенда
2. Убедитесь, что бэкенд запущен (проверьте `/health`)
3. Проверьте `FRONTEND_URL` в переменных бэкенда

### ❌ Проблема: Запросы отправляются, но данные не сохраняются

**Причины:**
1. Ошибка в `userController.js`
2. MongoDB недоступен
3. Неправильный `clientId`

**Решение:**
1. Проверьте логи бэкенда на ошибки
2. Убедитесь, что MongoDB запущен
3. Проверьте, что `clientId` генерируется правильно

### ❌ Проблема: MongoDB показывает ошибку подключения

**Причины:**
1. Неправильный `MONGODB_URI`
2. MongoDB сервис не запущен

**Решение:**
1. Скопируйте `MONGO_URL` из MongoDB сервиса в переменные бэкенда
2. Убедитесь, что MongoDB сервис активен

### ❌ Проблема: Данные сохраняются, но в другой коллекции/базе

**Причины:**
1. Неправильное имя базы данных в Mongoose

**Решение:**
- По умолчанию Mongoose использует имя базы из connection string
- Проверьте логи бэкенда - там должно быть указано имя базы

## Быстрая проверка чеклист

Выполните эти шаги по порядку:

1. ✅ Backend сервис существует и запущен
2. ✅ Backend логи показывают "MongoDB Connected"
3. ✅ `/health` endpoint возвращает `{"status": "OK"}`
4. ✅ Переменные окружения установлены правильно:
   - Backend: `MONGODB_URI`, `FRONTEND_URL`, `NODE_ENV`
   - Frontend: `REACT_APP_API_URL`
5. ✅ В консоли браузера нет ошибок
6. ✅ В Network видно запросы к `/api/user`
7. ✅ После добавления товара в корзину появляется запрос `/api/user/cart`
8. ✅ В MongoDB появилась коллекция `users`
9. ✅ В коллекции `users` есть документ с данными

## После выполнения всех проверок

Если всё настроено правильно, но данных всё ещё нет:

1. **Очистите кэш браузера** (Ctrl+Shift+Delete)
2. **Откройте сайт в режиме инкогнито**
3. **Добавьте товар в корзину заново**
4. **Проверьте логи бэкенда в реальном времени**
5. **Проверьте MongoDB через несколько секунд после действия**
